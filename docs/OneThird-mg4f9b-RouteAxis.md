## §1 — G1 and G2: the route axis, restored and declared

### 1.1 The mechanism mg-bd53 found, in one paragraph

Before mg-75f0 the four legacy comparisons ran the **gate's own** recomputation against the committed
value:

```python
rec["match_lambda_std"] = abs(rec["lambda_std"] - ref["lambda_std"]) < 1e-9
```

where `rec["lambda_std"]` is mg-4a86's `lambda_std`. After mg-75f0 the same key became an alias of the
row-wide comparison, which recomputes `lambda_std` through mg-8b64's `analyze_poset` → `transport_summary`
→ mgb0a6's `standard_block_and_lambda` — a different implementation in a different module. mg-4a86's route
was still called, still printed, and compared against nothing.

mg-75f0 saw this hazard and fixed it **for exactly one of the four quantities**, `bk_lambda2`, with a
comment saying why. `lambda_std` had the identical structure and `delta` a weaker version of it; neither
was mentioned.

**The reusable statement, and it is why G2 asked for it in the merge note:**

> **Comparing MORE fields against ONE route is not strictly better than comparing FEWER fields against TWO
> routes.** A single route detects a mutation that moves the stored value relative to the reference. A
> mutation that moves the computation *and* the compared value together is invisible to one route and
> fatal to two. A widening that trades routes for fields is a coverage change in **both** directions and
> has to be stated as one.

### 1.2 What the code now says, per comparison

`IDENTITY_SECOND_ROUTES` in the gate, one entry per compared legacy quantity, each stating one-route or
two-route **and why**. Machine-readable on purpose: `_identity_routes_declared()` is a gate condition, so a
fifth compared field with no declaration, or an entry whose reason decays to a stub, fails the gate rather
than waiting for the next audit.

| quantity | routes | second route | why |
|---|---|---|---|
| `num_LE` | **ONE** | — | both sides call the same `Poset.linext_count`. A second copy of the same DP is not a second route, and the gate has no independent linear-extension counter. Stated rather than left blank |
| `lambda_std` | **TWO** | `mg4a86.lambda_std` vs mgb0a6's `standard_block_and_lambda` | different implementations, different modules. **This is the one mg-75f0 removed** |
| `delta` | **TWO, weaker** | gate's `delta_and_frozen_pair` vs `mg8b64.bk_frozen_pair` | `before_prob_dp` is *shared*; only the aggregation differs. So it catches a mutated aggregation on either side and **not** a mutated pair probability, which would move both routes together. Half a second route, labelled as such |
| `bk_lambda2` | **TWO** | `mg4a86.bk_walk_matrix` vs `mg8b64.bk_walk_matrix` | the one mg-75f0 kept deliberately |

Each route is ANDed **into** `field_matches[field]`, not placed beside it — deliberately, because
mg-5ad1's part B2 perturbs one field at a time and calls `_identity_row_ok` on `field_matches` alone. A
route wired anywhere else would be invisible to the probe whose job is to enforce this gate. Part 1 of
`scripts/onethird_mg4f9b_route_axis_probe.py` asserts that placement.

   24 compared at >=1 of the 8 identity posets, 1 excluded with a reason, compared NOWHERE: none

### 3.1 (a) The mechanism, measured rather than asserted

The hypothesis to test was pm-onethird's: *is the reference independent of the code the mutation touches,
or does it descend from the same computation?*

It descends from the same computation. `scripts/onethird_mg4f9b_route_axis_probe.py` part 3 measures it by
doing what an author does — edit a probe, re-run it, commit the numbers:

| | mutation alone | mutation **+ the rows it moves regenerated by the mutated code** |
|---|---|---|
| **R1** = M3 (mg-5ad1's Theorem-E selector flip) on `mg75f0-widened` | exit **1**, 7/7 posets | exit **0**, **0 posets mismatch** |
| **R1** = M3 on `repaired` | exit **1**, 8/8 posets | exit **0**, **0 posets mismatch** |
| **R2** = M4 (mg-5ad1's rank filter) on `mg75f0-widened` | exit **1** | exit **1** (CONTROL B, CONTROL E, CONTROL F) |
| **R2** = M4 on `repaired` | exit **1** | exit **1** (CONTROL B, CONTROL E, CONTROL F) |

The regeneration is not partial or approximate: it rewrote all eight rows the gate looks up
(`enum-n7-#3,#20,#600,#945,#809,#52,#88` and `fam:N (2+2)`) with the mutated `analyze_poset`, and the
identity check then reported **`mismatched: none` at every one of them**. The mutation is fully present in
the running code and the gate has nothing left to notice it with.

`data/onethird-mg4f9b-route-axis.json`, part 3 rows.

**Read it as follows.** The identity check compares a recomputation against
`data/onethird-mg8b64-L1b-bk-transport-transfer.json`, which is not an independent reference: it is a
**frozen snapshot of the same code path**, produced by mg-8b64's own probe and committed. At *run time* the
two are genuinely independent — frozen bytes against a live computation — and that is real coverage, which
is why every mutation in the record above was caught by *something*. **Across commits they are not
independent at all.** The gate is a **regeneration detector**: it sees a mutation in the window between the
edit and the refresh, and it is blind the moment the two land together.

**And the refresh is not an attack — it is the normal authoring workflow.** Nothing in R1 is adversarial:
the mutation is applied, the probe is re-run, the numbers it now produces are committed. That is what a
careful author does, and it is what every commit in this repo that touches a probe and its dataset
together has done. So this control is defeated by *diligence*, not by malice — and that is a strictly
worse failure mode than a control that never fires at all, because **the more reliably an author refreshes
their reference data, the more reliably the check goes green.** A control that fires only in the window
between an edit and a refresh is one whose sensitivity is inversely proportional to how carefully the
corpus is maintained. (The framing is the mayor's, on reading the measurement; it is sharper than the one
this document had and is recorded with attribution rather than absorbed.)

That is the answer to (a), and it explains 0 for 2 without appeal to any property of the particular fields
compared. It is also **not** specific to `frozen_pair_overlap_with_U`. That quantity fails one step
earlier — the gate writes `data/onethird-mg2c34-n7-overlap.json` and never reads it back, so there is no
comparison at all — but a read-back would only move it into the R1 row: caught until someone regenerates
that file too. This is why the audit's suggested repair 2 is *worth doing and does not close the class*,
and it is why this ticket did not do it under the heading of closure.

### 3.2 (b) Can the gate close the class? ~~No.~~ — see the CORRECTION at the top of this file

**mg-48dd:** the paragraph below headed *"Widening cannot"* is correct and stands. The heading was not, and
the two were run together: a control need not be a widening and need not be a comparison. This section
evaluated one candidate (a read-back), rejected it correctly, and generalised. `CONTROL G` and `CONTROL H`
are counter-examples and are now in the gate.


**Widening cannot.** Widening the field axis (4 → 23 fields) and widening the route axis (1 → 3 two-route
quantities) both raise the number of ways a mutation can move the recomputation *away from the stored
value*. Neither changes **where the stored value came from**. A mutation that moves the computation and its
own reference together is invisible to any number of comparisons against that reference. That is a
statement about the shape of the check, not about how thorough anyone was.

**What does survive it — the same experiment's control, R2.** CONTROL A (`c = cos²θ`), CONTROL B (`c = 1`
on the antichain and `dim U = (n−1)²+1`), CONTROL C (the broken instrument must **not** return 1) and
CONTROL E (`dim U ≤ (n−1)²+1`, `dim U < |L|`) compare against **closed forms and theorems**, not against
stored numbers. M4 with the dataset regenerated exactly as R1's was is still exit 1: **regeneration cannot
move `(n−1)²+1`.**

So the useful distinction in this gate is not how many fields a control compares. It is **where its
reference comes from**. A new control is worth more than a wider comparison exactly when its reference is
one the corpus cannot regenerate. That is a design rule this arc can act on, and it is the one thing the
last two gate fixes did not have.

**Where the RESIDUAL class is detected: the independent audit stage, now 4 for 4**, by a party who reads the selector
and asks whether it is the right one — a semantic question no stored value can answer. This is recorded in
the gate's own header under `WHAT THIS GATE CANNOT SEE`, so that a reader of a green run knows what green
does and does not mean. A gate that documents what it cannot see is worth more than one that implies
coverage it has never had.
